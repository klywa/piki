# 对战截图解析 (Battle Screenshot)

**何时读**：输入含**对战画面**截图时。

> 队伍截图（Team Preview / 队伍编成 / 租借队码）走的是另一条路——见 `video-ingest.md`。
> 两者规则不同：队伍截图要落盘进附件目录（`vault.mjs` 的 `attachments.path`）并最终建卡；
> **对战截图喂给局面决策、不产生任何文件、不落盘。**

产物是一张**局面卡**，格式与 `turn-decision.md` 第 1 步完全一致，然后直接进入局面决策。

---

## 提取清单（按顺序，每项带置信标记）

1. **画面类型判定**——对战中（单打 1v1 / 双打 2v2）/ Team Preview / 选出画面 / 结算。
   **判错这一步后面全错**，所以先判并说出来。

2. **敌我区分**——己方通常在下方/近景且血条带数值；对方在上方/远景，只有血条长度。

3. **每只场上宝可梦**
   - 名称、等级、性别
   - **HP**：己方读数值 `x/y`；**对方按血条比例估，写成 `~65%±10%`，永不写成精确值**
   - 主要状态：毒（紫）PSN / 剧毒 TOX / 麻痹（黄）PAR / 烧伤（红）BRN / 冰冻（蓝）FRZ / 睡眠 SLP
   - 易变状态：替身、能力升降的箭头**及段数**、混乱、着迷、蓄力/半回合、道具已被击落
   - 若画面出现疑似太晶冠：**提示与 Champions 无太晶的规则冲突，请用户确认画面来源**

4. **场地条**——天气 + **剩余回合**、场地(terrain)、顺风/空间**计时**、反射壁/光墙/极光幕、
   单打的隐形岩/撒菱层数。
   **剩余回合数是一等决策输入，漏读必须显式标 `?`**，不能默认「还早」。

5. **己方可用招式**——名称 + PP `x/y` + 属性色块 + **是否变灰**。
   变灰本身泄露了对面的操作（回声虫/无理取闹/锁招道具），是免费情报。

6. **后备**——精灵球图标数量 = 存活数；可见者记名与血量。

7. **道具**——只写己方的、或对方已触发/已暴露的。
   对方未暴露的道具一律 `unknown`。可以给「常见道具及使用率」作为推断，
   但**必须与观测事实分行写，并标注 `（推断，来源 pokechamdb M-x 赛季）`**。

8. **名称核对**——读图得到的每个名字都过 `pokedb.mjs mon` 验证。
   形近中文名极易读错（九尾/阿罗拉九尾、一击流/连击流武道熊师），**这一步是硬性的**。

9. **产出局面卡** + 一行 `未知项：…`，交用户一次性确认，然后进入 `turn-decision.md`。

## 看不清时的规则

这些写死，不留解释空间——因为编造一个观测值比承认看不清危险得多：

- 逐项标 `?`。**绝不**用「常见情况」填补**观测项**（血量、状态、道具、已用招式）。
  推断可以有，但必须标成推断，且不能和观测混在同一行。
- **一次性列出所有看不清的项**，不要挤牙膏式追问。
- 判断每个未知项**是否会翻转结论**：
  - 不会翻转 → 直接给结论，附一句「即使 X 是 Y，结论不变」
  - 会翻转 → 给**条件式结论**，并只针对这一项追问
- 对方未暴露的招式写成「未知（常见配招：…，属推断）」，永远不写成既定事实。
- 图太糊 / 裁切不全 / 关键区域被挡 → **请用户重发或补一张，不靠猜**。

## 对战录像链接

- **Pokémon Showdown replay**：取 `https://replay.pokemonshowdown.com/<id>.log` 得纯文本战斗日志，
  按回合定位。日志里有双方的真实配置和每回合指令，信息量远大于截图——
  能拿到 log 就优先用它，并据此复盘「当时该怎么打」。
- **视频链接（YouTube / B站等）**：走 `scripts/fetch_video.py`，见 `video-ingest.md`。
  视频通常用于整理阵容和玩法思路，不适合定位单个回合的精确局面。

## 与队伍截图流程的分界

| | 对战截图（本文件） | 队伍截图（`video-ingest.md`） |
|---|---|---|
| 目的 | 定位当前局面 → 出决策 | 还原 6 只构成 → 建阵容卡 |
| 落盘 | **不落盘、不建卡** | 复制真实图片进附件目录（见 `note-conventions.md`），`![[文件名]]` 嵌入 |
| 产物 | 局面卡 + 本回合决策 | Obsidian 阵容笔记 |
| 血量/状态 | 必读 | 不适用 |

一张图同时含 Team Preview 和对战信息时，先问用户想要哪个，不要两条流程都跑。
