## 标签体系

必选 `宝可梦对战`，再从以下选**恰好一个**类型标签：

| 标签 | 适用范围 |
|---|---|
| `宝可梦` | 关于某个/某些具体宝可梦的知识 |
| `招式` | 关于招式（Move/技）的知识 |
| `特性` | 关于特性（Ability/特性）的知识 |
| `道具` | 关于道具（Item/もちもの）的知识，含树果、进化石、强化道具 |
| `基础` | 机制/概念/规则等基础知识 |
| `阵容` | 阵容（Team/構築）相关知识 |
| `技巧` | 对战操作/心理/决策技巧 |
| `状态` | 异常状态本身：烧伤/中毒/剧毒/麻痹/冰冻/睡眠等主要状态，及混乱/着迷等易变状态 |
| `天气` | 天气状态本身：晴天/下雨/沙暴/下雪，及其倍率与受益关系 |
| `场地` | 场地状态本身：电气/青草/薄雾/精神场地，及着地判定 |

每个类型标签对应 `templates/<标签名>.md` 一份正文模板，一一对应，无例外。

**扩展流程**：若以上均不合适，向用户提出新标签提案（给出名称+适用范围），用户采纳后在本表添加一行、新建对应模板，并更新 SKILL.md 的写卡流程表。

### 类型边界：一件事拆几张卡

`状态`/`天气`/`场地` 写的是**状态本身**，不是造出它的招式或特性。三者是三张卡，各写各的那一层，
靠双链串联，**内容不重叠**。否则同一组倍率会被抄进三张卡，改一处就漏两处。

以晴天为例：

| 卡 | 标签 | 只写 | 不写 |
|---|---|---|---|
| `大晴天` | `招式` | 威力/命中/PP/优先度/目标、这一招本身的用法与被守住等交互 | 晴天对火/水的倍率 |
| `日照` | `特性` | 触发时机、常见拥有者、如何被压制 | 晴天对火/水的倍率 |
| `晴天（天气）` | `天气` | 倍率、持续回合、受益方、受损方、反制 | 大晴天的 PP、日照的拥有者 |

场地同理（`电气场地` 招式卡 / `电气制造者` 特性卡 / `电气场地（场地）` 场地卡）；
状态同理（`鬼火` 招式卡 / `水幕` 特性卡 / `烧伤（状态）` 状态卡）。

三张卡的 frontmatter `related` 互相预留双链，哪张先建都不影响。

## 笔记命名

- 使用**中文描述性标题**（与 52poke/pokechamdb 中文名一致）
- 格式：`<中文名>.md`，**不在文件名中包含英文/日文**
- 示例：`喷火龙.md`、`拍落.md`、`气势披带.md`、`先制技优先级.md`
- 英文名、日文名、别名统一写入 frontmatter 的 `alias` 字段（供 Obsidian 别名搜索）
- 阵容笔记：`<核心策略描述>阵容.md`，如 `Mega喷火龙单打阵容.md`

### 命名限定语（避免与本 vault 其他领域笔记冲突）

本 vault 是综合知识库（含 RL/ML/AI 等领域）。建卡前判断标题是否**过于通用、可能与其他领域撞名**，必要时加限定语：

- **专有名词不加限定**：宝可梦/招式/特性/道具名本身唯一，直接用原名（`拍落.md`）。
- **通用词加限定**：当标题是通用术语（"伤害计算""属性相性""天气""暴击"等其他领域也会用的词）时，加 `宝可梦`/`宝可梦对战` 前缀消歧。
  - 示例：`宝可梦对战伤害计算.md`、`宝可梦属性相性.md`，而非裸名 `伤害计算.md`、`属性相性.md`。
- 双链同步使用加限定后的完整标题，正文用管道别名（如 `[[宝可梦属性相性|属性相性]]`）；裸名可作为 `alias` 备查。

### 状态/天气/场地笔记的类型后缀（必做）

这三类笔记的标题**一律**加全角括号类型后缀 `（状态）`/`（天气）`/`（场地）`，不做「这个会不会撞名」的判断——
因为实测下来每一个都会撞：

- **裸名已被同名招式占用**：`沙暴`(Sandstorm)、`剧毒`(Toxic)、`电气场地`/`青草场地`/`薄雾场地`/`精神场地`
  都是招式名。**裸名归招式卡所有**，状态卡让位。
- **裸名是通用词**：`晴天`、`下雨`、`烧伤`、`麻痹`、`睡眠`、`混乱`、`中毒` 在本 vault
  （含 RL/ML/AI 笔记）里都可能被其他领域占用。

写法与规则：

- 格式 `<中文名>（状态）.md`、`<中文名>（天气）.md`、`<中文名>（场地）.md`，全角括号 `（）`。
- 示例：`烧伤（状态）.md`、`剧毒（状态）.md`、`沙暴（天气）.md`、`电气场地（场地）.md`。
- 双链同步带后缀，正文用管道别名：`[[沙暴（天气）|沙暴]]`、`[[烧伤（状态）|烧伤]]`（表格内转义为 `\|`）。
- 裸名写进 `alias`（如 `沙暴`），Obsidian 搜裸名照样能找到。
- `alias` 还要带上 `calc.mjs` 用的取值——天气 `晴/雨/沙/雪`、场地 `电气/青草/精神/薄雾`、
  状态 `烧伤/麻痹/中毒/剧毒/睡眠/冰冻`——让笔记与精算脚本共用一套词汇。
- **仅这三类加后缀**。招式/特性/道具是专有名词，保持裸名。

### 宝可梦笔记的模式后缀（单打/双打）

**「宝可梦」类型笔记**（描述某只具体宝可梦的对战配置）必须在标题末尾加模式后缀 `（单打）` 或 `（双打）`，因为同一宝可梦在单/双打的配招、定位差异很大，需分卡区分：

- 格式：`<中文名>（单打）.md`、`<中文名>（双打）.md`（使用全角括号 `（）`）。
- 示例：`阿罗拉九尾（单打）.md`、`喷火龙（双打）.md`。
- 双链同步带后缀：正文用管道别名 `[[阿罗拉九尾（单打）|阿罗拉九尾]]`（表格内转义为 `\|`），
  frontmatter 的 `related` 可直接写 `"[[阿罗拉九尾（单打）]]"`；英文/日文名仍写入 `alias`。
- **互链另一模式（必做）**：「宝可梦」类型笔记的 frontmatter `related` 字段**必须**包含指向同一宝可梦另一打法模式的双链——单打卡链到双打卡、双打卡链到单打卡。若对应模式的卡尚未建立，**也要先预留好该双链**（Obsidian 中显示为未创建链接，待日后建卡即自动生效）。
  - 示例（`阿罗拉九尾（单打）.md` 的 frontmatter）：
    ```yaml
    related:
      - "[[阿罗拉九尾（双打）]]"   # 预留：双打卡未建也先写上
    ```
- 若同一宝可梦单、双打都建了卡，二者在 `## see also` 中亦可互链。
- **仅「宝可梦」类型加此后缀**。招式/特性/基础属机制类知识，与对战模式无关，**不加**；阵容类已在命名（如 `XX单打阵容`）与 frontmatter 中体现模式，亦不另加。

## 双链规则（[[wikilink]]）

以下情况**必须**用 `[[xxx]]` 双链（条目不存在也先预留）：
1. 提及已有 Obsidian 笔记
2. 提及宝可梦专有概念（如[[先制技]]、[[属性相性]]、[[超级进化]]）
3. 提及具体宝可梦（如 `[[喷火龙（双打）|喷火龙]]`——带后缀，见下方管道别名规则）
4. 提及具体招式（如[[拍落]]、[[地震]]）
5. 提及具体特性（如[[猛火]]、[[沙暴造物]]）
6. 提及具体道具（如[[气势披带]]、[[剩饭]]）
7. 提及具体类型标签（如[[宝可梦对战]]、[[基础]]）

**双链统一使用中文名**（英文/日文名已通过 `alias` 字段可供 Obsidian 搜索，双链中不重复写）。

### 引用带后缀的笔记：必须用管道别名 `[[全名|裸名]]`

带后缀的笔记（宝可梦的 `（单打）`/`（双打）`、状态/天气/场地的 `（状态）`/`（天气）`/`（场地）`、
以及加了限定语的标题）**一律写成管道别名形式**——链接指向完整文件名，显示文字用裸名：

```markdown
[[洗翠风速狗（双打）|洗翠风速狗]]     ✅ 按文件名解析，正文读起来仍是裸名
[[沙暴（天气）|沙暴]]                 ✅
[[洗翠风速狗]]                        ❌ 不要裸名——只能靠 alias 兜底，链接会断
[[洗翠风速狗（双打）]]                 ⚠️ 能解析，但正文里带后缀读着别扭；仅 frontmatter 可这样写
```

**为什么**：裸名 `[[喷火龙]]` 从来不匹配任何文件名，只能靠 frontmatter `alias` 字段的
遗留解析行为兜底，并不可靠（现代 Obsidian 属性是 `aliases`，vault 里写的却是 `alias`）。
管道别名让链接按**文件名**解析，与 alias 无关，才是稳的。

**表格内必须转义管道**：Markdown 表格用 `|` 分列，链接里的裸 `|` 会切断单元格、直接把表格
打散。凡在表格行内，写成 `\|`：

```markdown
| 1 | [[雷丘（双打）\|雷丘]] | [[电磁炮]] |     ✅
| 1 | [[雷丘（双打）|雷丘]] | [[电磁炮]] |      ❌ 表格被打散
```

表格外（正文、引用块、列表、frontmatter）用普通 `|`，**不要**转义。

**不带后缀的笔记不要加管道别名**——招式/特性/道具是裸名文件，`[[拍落]]` 直接就能解析，
写成 `[[拍落|拍落]]` 纯属噪音。

`## see also` 节用纯 `[[链接]]` 罗列相关笔记，不写双链之外的说明文字（简洁优先）。

**格式要求**：see also 内容必须是**列表**（每行以 `- ` 开头）。紧密关联的笔记可放在同一行，但需用**顿号「、」**隔开。示例：

```markdown
## see also

- [[宝可梦对战]]
- [[宝可梦属性相性]]、[[有色眼镜]]、[[厚脂肪]]
```

## 数据来源 (Sources)

数据来源记录在 frontmatter 的 **`url` 属性**中，**不单独创建「## 数据来源」章节**：

- `url` 用 YAML 列表，每项一个来源；竞技数据务必标注赛季与对战模式。
- 资料类来源直接填页面 URL；竞技数据类可填「来源名 + 赛季/模式」描述（无固定页面时）。

示例：

```yaml
url:
  - https://bulbapedia.bulbagarden.net/wiki/Aurora_Veil_(move)
  - "pokechamdb：M-3 赛季单打使用率"
```

## 附件规则 (Attachments)

阵容笔记来自**图片/截图**时，图片要作为附件嵌入笔记：

- **附件目录**：`D:\Vaults\AIO\Attachments\`（已由 vault 的 `.obsidian/app.json` 指定为附件根目录）。
- **落盘要求**：嵌入前必须把**真实图片文件**复制进该目录。用户给路径就复制；用户在对话里粘贴图片，则由 piki 把粘贴图的临时文件落盘到此目录。**取不到原始文件时请用户补文件/路径，绝不重绘失真图冒充。**
- **命名**：描述性英文/拼音皆可，形如 `<阵容名>-team.png`（如 `mega-charizard-singles-team.png`）。同一阵容多图加序号 `-1`/`-2`。
- **嵌入语法**：在笔记 `## 阵容图` 章节用 `![[文件名]]`（按文件名引用，Obsidian 自动解析 `Attachments\` 下同名文件，不写完整路径）。
- **来源链接**：视频/图片的来源 URL 写入 frontmatter 的 `url` 字段，不另开「数据来源」章节（见上）。

详细采集流程见 `references/video-ingest.md`。

## 原子性原则

- 每篇笔记 self-contained、不可再拆
- 一篇笔记只表达**一个核心概念**
- 宝可梦条目：只写对战相关内容（不写生活习性、出现地点、图鉴描述）
- 若内容自然分拆为两个独立概念，建两张独立笔记并互链

## 输出语言规范

- 笔记正文使用**中文**
- 宝可梦名称格式：`中文名 (English/英語)`，首次出现时附日文：`中文名 (English/英語・日本語名)`
- 招式、特性、道具同上：`中文名 (英文名/英語名・日文名/日本語名)`
- 示例：`喷火龙 (Charizard・リザードン)`、`拍落 (Knock Off・はたきおとす)`、`气势披带 (Choice Scarf・こだわりスカーフ)`
